# 冻存条码核对器（cryobcode）

一个运行在浏览器里的冻存样本条码核对工具：扫冻存盒上的一维条码，实时判断是否在留存名单内，并显示盒内每支样本管的位置。单文件即可运行、离线可用、数据不出设备——适合实验室自发分发，不需要任何服务器支持（也可以部署到任意静态站点）。

## 功能特性

- **多种识别方式**：手机摄像头连续扫码（Code128 / Code39 / EAN / ITF / Codabar / UPC）；**USB / 蓝牙扫码枪**（HID 键盘模式，页面保持打开直接扫，无需点击输入框）；相册照片识别（多尺度 + 中央裁剪自动重试）；手动输入兜底；
- **以盒为单位核对**：条码取「暂存空间」末尾的盒编码（如 `2026年示例组第1盒E7000001` → `E7000001`）；命中弹出制式冻存盒（默认 6 行 × 8 列，可配置）的孔位俯视图，绿点标出每支样本管位置，清单列出「行 · 列 + 样本号 / 冻存条码号」；清单与孔位点击联动高亮；
- **盘点辅助**：实时统计（已扫 / 库外 / 待找）、扫描记录（可搜索、可删除单条）、「待找清单」（还没扫到的盒子及位置）、CSV 导出（Excel 直接打开）；
- **隐私自控**：编码库内嵌在页面文件里，数据只存在使用者浏览器本地（localStorage），无账号、无后端、无上报；构建时**自由选择明文或 AES-256 加密内嵌**（加密版打开需密码，适合把页面放到公开网址的场景）；
- **离线 PWA**：添加到手机主屏幕后点图标秒开、断网可用；更新走后台静默换装。

## 快速开始

**在线体验（演示数据）**：<https://lugoudu.github.io/cryobcode/>

自己构建三步：

```bash
# 1. 准备名单 Excel（格式见下），装依赖
pip3 install openpyxl cryptography pillow

# 2. 构建单文件网页（明文，本地/内网分发）
python3 build.py 你的名单.xlsx

# 3a. 或者构建加密 PWA（公网分发推荐）
python3 build.py 你的名单.xlsx --encrypt --pwa --out site
#     密码会打印出来（或存 password.txt，该文件已 gitignore）

# 3b. 部署 site/ 目录到任意静态站点（GitHub Pages、对象存储、自建服务器均可）
```

`python3 build.py --help` 查看全部选项（库名、盒型 `--grid 8x12`、输出路径等）。不带参数时用 `demo/demo.xlsx` 演示数据构建。

## 名单 Excel 格式

第一个工作表，首行为表头，识别以下列（列名包含关键词即可，顺序不限）：

| 列 | 作用 | 必填 |
|----|------|------|
| 暂存空间 | 末尾 E 开头的盒编码（**核对用条码**）与盒名 | ✅ |
| yangbenhao / 样本号 | 每支样本管编号 | 建议 |
| 冻存条码号 | 单管条码（展示用，不参与判定） | 建议 |
| 行索引 / 列索引 | 盒内孔位（用于网格落点） | 建议 |

同一个盒编码可对应多支样本管（一盒多管是常态）。仓库自带的 `demo/demo.xlsx` 是可参考的假数据示例。

运行中换库：页面「编码库」页直接上传新 Excel（或手工添加/删除编码），无需重新构建；换库保留扫描记录。

## 隐私与加密

- **明文构建**：编码库直接内嵌页面。适合内网、点对点发送（微信文件/AirDrop/U盘）等受控分发；
- **加密构建**（`--encrypt`）：编码库以 AES-256-GCM 加密内嵌（PBKDF2-SHA256 15 万次迭代派生密钥），打开页面需输入一次密码，之后本机免密。适合部署在公开网址——**没有密码的人拿不到任何名单内容**；
- 两种模式可随时互换：同一份 Excel 重新构建即可；扫描记录、手工添加的编码都存在浏览器本地，不上传任何地方；
- `password.txt` 已被 .gitignore 排除，不会进入版本库。

## 使用方式

- **手机**：Safari 打开 → 解锁 → 分享 →「添加到主屏幕」，之后点图标使用（全屏、离线）。微信内打开无法调用相机，需「在浏览器打开」；
- **电脑 + USB 扫码枪**：页面保持打开，扫码枪对准条码直接扫（扫码枪为键盘设备，页面全局聚合快速键入，人工打字不会误触发）；扫描枪后缀建议设为回车，无后缀模式亦支持；
- **声光反馈**：命中绿屏 + 双高音 + 弹盒内图；未命中红屏 + 低音 + 长震动。

## 部署选项

| 方式 | 说明 |
|------|------|
| 单文件直发 | 构建 HTML 文件直接发给使用者，双击/本地打开即可（摄像头需 HTTPS 环境，扫码枪、手查、记录不受限） |
| GitHub Pages / 对象静态站 | 把 `--pwa` 输出目录推上去即可，自带 HTTPS 与离线缓存 |
| 自有服务器 | 任意静态服务器 + TLS 即可（示例：Caddy `:9443 { tls <crt> <key>; root * <dir>; file_server }`；IP 直连可用自签证书，仓库 `setup.html` 提供 iPhone 信任引导页） |
| 局域网 | `python3 serve_https.py` 一键自签 HTTPS（自动打印访问二维码） |

## 常见问题

- **摄像头无法访问**：浏览器要求 HTTPS（或 localhost）；微信内置浏览器不支持相机，请用 Safari/Chrome 打开；
- **更新版本**：PWA 缓存优先 + 后台更新——手机上「打开 → 完全关闭 → 再打开」一次即可拿到新版；
- **盒型不是 6×8**：构建时 `--grid 8x12` 等按需指定；行列超出盒型的样本会在清单中标注「超位」；
- **相册识别失败**：页面会自动做缩放与裁剪重试；HEIC 原图请先截图再选。

## 项目结构

```
app_template.html     页面模板（数据与扫码库在构建时注入）
build.py              构建脚本（读 Excel → 明文/加密 → 单文件或 PWA）
html5-qrcode.min.js   扫码引擎（内联进产物，离线可用）
serve_https.py        局域网自签 HTTPS 一键服务
setup.html            自签证书 iPhone 信任引导页（PWA 构建自动带上）
demo/demo.xlsx        演示名单（假数据）
testimg/              测试条码图（假码，生成脚本见 README 附录）
```

测试条码图生成：`pip3 install python-barcode pillow` 后用 Code128 生成任意编码图片即可（`barcode.get('code128', 'E9000001', writer=ImageWriter()).save('testimg/x')`）。
